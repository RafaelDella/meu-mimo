# T11 Album Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** entregar álbum privado por ticket com upload existente, publicação explícita, remoção própria, aviso agrupado e retenção vinculada à origem real.

**Architecture:** um agregado versionado liga ticket e coleção MEMORY; eventos e itens imutáveis confirmam publicação/remoção com mídia e outbox. O pipeline T06 continua responsável por bytes, partes, processamento e expurgo. As transações da origem sincronizam retenção sem modificar a economia do ticket.

**Tech Stack:** Next.js/React/TypeScript, Prisma/PostgreSQL, Supabase Auth/Storage locais, node:test e Playwright existentes.

**Spec:** [desenho T11 confirmado](../specs/2026-10-22-t11-album-design.md). O idealizador autorizou implementação após T10 e commit; método Toolkit e sequência até T15 preservados.

## Global Constraints

- **Pré-condição:** terminar suites/correções/revisão e commit de T10 antes de executar este plano. Esta preparação documental não inicia T11.
- Até vinte itens ativos por álbum, incluindo publicados, rascunhos, falhas e envios em andamento; até dez por lote de upload/publicação.
- Legenda simples opcional até500 caracteres Unicode; espaços viram vazio. Legenda/ordem publicadas imutáveis; novos lotes acrescentados ao fim.
- Fotos JPEG/PNG/WebP até10.000.000 bytes; vídeo MP4/MOV até100.000.000 bytes/60s. Preservar conversão, limites de derivados, checksums, leases e URLs de cinco minutos T06.
- Cancelado permite consulta/remoção própria, mas bloqueia novas reservas, continuação de partes e publicação. Demais estados permitem novas memórias se audiência/prazo autorizarem.
- Pausa não inicia prazo; primeiro encerramento da loja/participação inicia doze meses de calendário. Pendência protege existentes, mas não estende prazo para novas memórias.
- Realizar/cancelar libera hold e aplica prazo contado do encerramento original, inclusive se já vencido; semhold, leitura nega derivados vencidos antes da manutenção.
- Reutilizar `MediaUploader`; nenhuma segunda implementação de partes/processamento. Sem dependências, serviços pagos ou publicação novos.
- Nenhuma migração aplicada muda, especialmente T09/T10. Preservar alterações locais e não versionar credenciais/artefatos. JS/TS até350linhas por arquivo.
- Root é o único executor de Git, commits, typegen, builds, serviços, bancos e suites; processos/portas compartilhados ficam em série.

## Interfaces compartilhadas fixadas antes da onda1

### Persistência

- `TicketAlbum`: `id UUID` (intenção de iniciar), `storeId UUID`, `redemptionId UUID unique`, `participantMembershipId UUID`, `collectionId UUID unique`, `createdByProfileId UUID`, `version Int default1`, `nextPosition Int default1`, `createdAt timestamptz`.
- `AlbumEvent`: `id UUID` (UUID de publicação; UUID do servidor na remoção), `albumId UUID`, `storeId UUID`, `redemptionId UUID`, `actorProfileId UUID`, `version Int`, `kind String` (`PUBLISH|REMOVE`), `requestDigest String` (SHA256), `removedAssetId UUID? unique`, `createdAt timestamptz`. `@@unique(albumId,version)` e `@@unique(id,albumId,storeId)`.
- `AlbumItem`: `assetId UUID @id`, `albumId UUID`, `publicationId UUID` (AlbumEvent PUBLISH), `storeId UUID`, `position Int`, `caption String default''`, `createdAt timestamptz`; `@@unique(albumId,position)`. Itens não são apagados/atualizados quando MediaAsset é removido.
- `OutboxEvent.albumEventId UUID?`, `NotificationKind.ALBUM_PUBLISHED`. Chave `album.published:{publicationId}`; origem tipada exige redemptionId e albumEventId e impede fontes incompatíveis.
- Relações Prisma simples e FKs compostas SQL preservam ticket/loja/participação, coleção/loja, evento/álbum/loja e arquivo/coleção. SQL confere collection.purpose=MEMORY, subjectId=ticket.id, mesma participação e autoria MERCHANT atual.
- Eventos/itens recebem SELECT/INSERT, sem UPDATE/DELETE. TicketAlbum permite somente atualização version/nextPosition. Guardas diferidas exigem projeção/evento/itens/publishedAt/outbox coerentes e uma remoção autoral por asset.

Criar a coleção e TicketAlbum na mesma transação. Nova coleção MEMORY só pode
confirmar se houver agregado/origem real; guardas diferidas permitem essa
ordem. Coleções fictícias anteriores são preservadas, mas ficam inacessíveis
nas APIs/gateway; não apagar ou associar automaticamente a um ticket aleatório.
Não acrescentar flag de ambiente que relaxe essa regra.

### DTOs em `web/src/contracts/albums.ts`

```ts
type AlbumPreview = { publishedCount: number; thumbnailAssetId: string | null };
type AlbumItemView = { assetId: string; caption: string; position: number;
  publishedAt: string; mediaType: 'PHOTO' | 'VIDEO'; width: number; height: number;
  durationMs: number | null; canRemove: boolean };
type TicketAlbumPage = PageResult<AlbumItemView> & {
  id: string | null; storeId: string; ticketId: string; version: number;
  collectionId: string | null; // somente lojista recebe ID da coleção
  permissions: { canStart: boolean; canUpload: boolean; canPublish: boolean };
  unavailableReason: 'CANCELLED' | 'RETENTION_EXPIRED' | null };
type AlbumPublicationBody = { operationId: string; expectedVersion: number;
  items: { assetId: string; caption: string }[] };
type AlbumPublicationView = { id: string; version: number; createdAt: string;
  assetIds: string[] };
type AlbumPublicationMutation = { album: TicketAlbumPage;
  publication: AlbumPublicationView; appliedVersion: number };
type AlbumPublicationLookup = { operation: AlbumPublicationMutation | null };
```

Exportar os tipos; importar `PageResult` de stores. Álbum ausente usa id/null,
version0, itens vazios, coleção null; GET não cria. `canRemove` independe de
canUpload e exige autoria atual. Metadados de rascunho continuam em `MediaPage`
autorizado somente ao autor. Nenhum DTO inclui URL permanente, Storage key,
checksum, nome original ou destinatário. `TicketView.album:AlbumPreview` é
obrigatório; preview aplica visibilidade/retention atuais, sem chamada por item
do cliente. Atualizar todos os fixtures DTOs antigos com preview vazio.

### API e funções

Base `A=/api/lojas/:storeId/tickets/:ticketId/album`:

| Rota | Corpo/retorno | Função em `server/albums/service.ts` |
| --- | --- | --- |
| GET A | paginação20/50 → TicketAlbumPage | `readTicketAlbum(identity,storeId,ticketId,query?):Promise<TicketAlbumPage>` |
| POST A/iniciar | `{operationId}` → `{album:TicketAlbumPage}`,201 inclusive recuperação | `startTicketAlbum(identity,storeId,ticketId,body):Promise<{album:TicketAlbumPage}>` |
| POST A/publicacoes | AlbumPublicationBody → AlbumPublicationMutation,200 | `publishTicketAlbum(identity,storeId,ticketId,body):Promise<AlbumPublicationMutation>` |
| GET A/operacoes/:operationId | AlbumPublicationLookup,200 | `lookupAlbumPublication(identity,storeId,ticketId,operationId):Promise<AlbumPublicationLookup>` |

`identity:Identity`, IDs:string, body:`Record<string,unknown>`, query
`URLSearchParams` opcional. Rejeitar campos extras, item duplicado, lote vazio
ou>10, legenda501/Unicode inválido e versão inválida. Lookup não revela outra
origem/autor; recuperar replay antes de validar estado/versão novos, após acesso.
UUID de iniciar já usada em outra origem gera409; iniciar novamente o mesmo
ticket recupera seu agregado, nunca outra coleção.
Autoria de iniciar/publicar exige Membership.role=MERCHANT e vínculo atual,
sem usar requireMerchant que rejeita closedAt: encerramento permitido em D03
não equivale a revogação. Participante nunca ganha esses comandos.

Interfaces internas, sem nova transação aninhada:

- `requireAlbumOrigin(scope:StoreScope, collection:MediaCollection):Promise<{album:TicketAlbum;ticket:Redemption}>` em `server/albums/access.ts`; verifica origem real também nas rotas genéricas/gateway.
- `albumRetention(scope:StoreScope,ticket:Redemption,now:Date):Promise<{closedAt:Date|null;until:Date|null;hold:boolean;expired:boolean}>` em `server/albums/retention.ts`; primeiro encerramento, calendário e hold.
- `syncAlbumRetention(scope:StoreScope, input:{ticketId?:string;membershipId?:string}={}):Promise<void>` no mesmo módulo; atualiza coleções da loja filtradas sem abrir outra transação. Usar `setMediaRetention` existente.
- `recordAlbumRemoval(scope:MediaAssetScope,now:Date):Promise<void>` em `server/albums/removal.ts`; chamada por removeMedia antes da ocultação, mesmo lock; ignora repetição já removida. Evento REMOVE com digest de `{assetId}`, version+1, nextPosition preservado.
- `albumPreview(scope:StoreScope,ticketId:string):Promise<AlbumPreview>` e `albumPage(scope, ticket,query):Promise<TicketAlbumPage>` em `server/albums/views.ts`.
- `enqueueAlbumPublished(tx:StoreTransaction,eventId:string):Promise<void>` em `server/outbox/events.ts`; autor vem de evento e destinatário é participante atual, inclusive vínculo encerrado autorizado.

Ampliar MediaScope com `memoryPolicy?:{albumId:string;ticketId:string;
authorProfileId:string;cancelled:boolean;expired:boolean;hold:boolean}`,
carregada em requireMediaCollection após requireAlbumOrigin/albumRetention.
`assertMediaUpload` e `assertMediaRead` continuam síncronos, consumindo essa
política já revalidada; EVIDENCE não recebe memoryPolicy. Retorno de leitura
e preview filtra mídias vencidas semhold; conhecer a coleção não expõe rascunhos.

Guardas de upload usam cancelamento/prazo em reserva, partes, conclusão,
e publicação, sem bloquear leitura/remoção própria
de cancelado. GET/Range e emissão/renovação de URL usam proteção/prazo atuais.
Worker não ganha audiência; revalidar após Storage como T06 já exige.

### Transação e ordem

Identidade/sessão → loja → participação → coleção/álbum → assets ordenados.
Na publicação: autorizar → lock UUID → replay → estado/prazo/versão/capacidade
→ validar todos selecionados READY e não publicados/removidos → criar evento
PUBLISH → itens com posições nextPosition..nextPosition+N-1 → publishMedia
→ version+1/nextPosition+N → outbox única. Todos confirmam juntos; nenhum byte
ou FFmpeg dentro da transação. Um asset publicado por outra intenção gera409.

Remoção explícita mantém rota genérica `/midia/arquivos/:assetId/remover` e seu
retorno MediaAssetView; não cria API concorrente. Registrar evento/revisão e
ocultar no mesmo commit; replay pela própria UUID do asset é seguro. Expiração
automática é manutenção T06, sem atribuir uma ação humana fictícia: a política
já retira visibilidade antes do worker, e os estados da mídia impedem publicar
arquivo vencido/removido, mesmo se a revisão do agregado não tiver mudado.
Antes de incrementar, conferir que version/nextPosition não excederão o inteiro
PostgreSQL; responder409 para consulta em vez de permitir overflow.
